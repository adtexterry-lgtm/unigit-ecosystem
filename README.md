## AI should work for everyone

**UNIGIT is an AI workbench built for real work.**

It brings models, tools, files, and project context into one clear environment. People describe the outcome they want; the model can choose a path, use the tools available, work with real files, and return something genuinely usable.

**No model-subscription maze. No API expertise. No rigid “AI workflow” to learn. Open UNIGIT, state the goal, and start working.**

> Move from “I heard AI can do that” to “I can get it done now.”

## From answers to outcomes

Many AI products stop at the response. UNIGIT cares about what happens next.

| What people actually need | What UNIGIT is designed to provide |
| --- | --- |
| The right model for the job | Smart routing that reduces choice overload while preserving model preference |
| Complex work completed | Stable, clearly named tools and honest environment feedback—not a forced workflow |
| Real files handled | Documents, spreadsheets, presentations, images, and project files in one task context |
| A usable deliverable | Files that truly exist and can be previewed, opened, saved, and revised |
| Work that keeps moving | Provider failover where possible, with context, state, and finished work preserved |
| Clear usage and cost | Calls, status, results, and cost recorded without unnecessary gates |

## A workbench that supports the model

UNIGIT should not tell every model: “First do A, then B, then C.” It should:

- provide a stable, simple, legible tool set;
- state what resources and permissions are available;
- return honest feedback from the system, files, browser, and execution environment;
- record cost, state, and results;
- switch providers when a route fails; and
- carry project context forward so work can continue.

In short: **a thin harness, broad compatibility, strong tools, and real delivery.**

## What this repository is

This is UNIGIT’s **public brand and ecosystem hub**. It is not the source repository for the proprietary product runtime.

This repository exists to:

- explain the product direction, vision, and values;
- publish approved public brand materials and safe synthetic examples;
- discover models, tools, MCP servers, skills, templates, and knowledge resources worth exploring;
- give capability builders, providers, domain experts, and partners a clear point of contact; and
- publish stable extension contracts only when they are ready to be maintained publicly.

It does **not** contain private routing, billing, provider operations, server code, admin code, desktop execution, internal harness logic, private tool implementations, commercial strategy, credentials, production configuration, customer data, or private repository history. See the [public boundary](./docs/OPEN_SOURCE_SCOPE.md).

## What we are looking for

We welcome public, verifiable resources that can help real users complete real work:

- dependable model and inference capacity;
- practical MCP servers, tools, skills, and automation capabilities;
- capabilities for documents, design, software, research, data, and professional work;
- legally usable knowledge sources, connectors, and templates;
- user-friendly products, channels, and ecosystem partnerships; and
- early users willing to test, co-create, and share grounded feedback.

→ [Recommend a resource](../../issues/new?template=resource.yml) · [Propose a partnership](../../issues/new?template=partnership.yml)

## Value for the ecosystem

### For users

Less configuration and less switching between products—so AI moves from talking about work to doing it.

### For capability builders

Bring useful tools, templates, and professional capabilities into real tasks, with a clear path to discovery and collaboration.

### For model and infrastructure partners

Connect model capability to real user demand across files, tools, long-running work, and persistent project context.

### For industry and channel partners

Help bring practical AI to people who previously lacked the time, technical background, or purchasing access to use it.

## Product direction

**Now** — Models use tools, work with files, and deliver results inside a clear workbench.

**Next** — Missing capabilities can be discovered, authorized, installed, and used within the same task.

**Future** — A capability marketplace, knowledge base, and intelligent workbench form an open ecosystem for real work.

These are directions, not delivery-date commitments. Refer to the [official website](https://unigit.ai/) and release notes for the currently available product.
